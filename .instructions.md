# Instructions for AI Agents

Before making any changes to this codebase:

1. **Read `ARCHITECTURE.md`** to understand how systems interconnect. This is not a simple single-page app — it has two pages communicating via localStorage, independent timers on each page, sounds triggered only on the display page, and multiple systems sharing the same state object.

2. **After making changes** that affect any documented system, update the relevant sections of `ARCHITECTURE.md`.

## What Counts as an Architecture Change

Update `ARCHITECTURE.md` if you:
- Add, rename, or remove a key from `timerState`
- Add or modify timer states / display types / timer modes
- Add, remove, or rewire a sound trigger
- Add a new modal
- Change CSV import logic or the match/team data structure
- Add or move CSS files or move styles between files
- Change how cross-tab communication works

## Critical Gotchas

These are not obvious — read them:

- **State updates go through `updateState(timerState)` in `script.js`**, which writes to localStorage AND dispatches a StorageEvent. Writing localStorage directly won't notify the display page.

- **Sounds live in `display.js`, not `script.js`.** The control page only sets `soundOption`; the display page decides what plays.

- **Display type and timer mode changes are blocked while the timer is running.** Respect this gate.

- **Adding a new `timerState` key requires updating `defaultState` in `script.js`** so the spread-merge in `loadState()` handles existing saved states. Also update `defaultDisplayState` in `display.js` if the display page reads it.

- **`tableNames.length` drives team card count** (2 or 4). It also sets match schedule table columns and each match's `teams` array length.

- **CSS for the display page is in `css/display.css`; control page layout is in `css/control.css`.** Don't mix them.

- **`TIMER_DURATION` is defined in both `script.js` and `display.js`** and must match.

See `ARCHITECTURE.md` for the full system reference.
